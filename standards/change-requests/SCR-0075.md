## 1. Zweck

Der SCR-0074-Compliance-Scan lief als Ad-hoc-Skript. Per Owner-Direktive wird er
als wiederverwendbares Tool `org_compliance_scan.py` im `.github`-Hub verankert,
damit er **bei jedem SCR-Abschluss automatisch** läuft statt situativ gebaut zu
werden — plus wöchentlicher GitHub-Action-Lauf als Sicherheitsnetz.

## 2. Umfang des Tools

100 % API-getrieben (GitHub-Tarballs, keine lokalen Klone erforderlich):

1. **MUST-Artefakte** — 11 Pflichtdateien je Produkt-Repo (ATC-STD-201)
2. **Governance-CI** — `.github/workflows/` vorhanden
3. **Compliance-Badge** — `ATC COMPLIANCE`-Zeile im README (Regex `ATC[\s-]*COMPLIANCE`)
4. **Lizenz-Konsistenz** — LICENSE=Apache-2.0; keine proprietary/ARR/UNLICENSED-Reste
   in README, `.atc/`, Cargo.toml, package.json (inkl. Subtrees, Archive exkludiert;
   `licenses/` im Standards-Repo ausgenommen — beschreibt Lizenz-TYPEN, keine Zuordnung)
5. **Claim-Ehrlichkeit** — kein Build/Tests-PASS-Claim in STATUS.md ohne Implementierungsdateien
6. **Spec-Abdeckung** — `docs/specs/` oder `specs/` (Doku-/Standards-Repos: EXEMPT)

Ausgabe: JSON + Markdown-Report, Konsolentabelle, `--strict` für CI-Gates
(Exit 1 bei Findings), EXEMPT-Klassen (`.github`, `atc-standards`,
`a-townchain-os-docs`, `demo-repository`/F-059).

## 3. Verankerung

- **GitHub Action** `org-compliance-scan.yml`: wöchentlich (Mo 05:00 UTC) +
  `workflow_dispatch`, Report-Commit (continue-on-error bei Branch-Protection) +
  Artifact-Upload.
- **SCR-Prozess**: Agent-Koordination im Hub —_org_compliance_scan.py ist Pflicht-
  Bestandteil jedes SCR-Abschlusses_ (Katalogsiehe Hub-AGENTS.md).
