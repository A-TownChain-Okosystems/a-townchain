## Proposed Change
Physische Umsetzung der §34-Standard-Integritaet im atc-standards-Repository:
(1) CODEOWNERS (heute angelegt), (2) Protected main mit Required Reviews,
(3) Immutable Tags je Release, (4) Secret/Dependency-Scanning via CI,
(5) Signed Releases.

## Motivation
Security Review S-F01 (07.09.2026): registry/standards.yaml ist Single Point
of Trust; main ist aktuell ohne Zweig-Absicherung (direkte Pushes moeglich).
§34 benennt die Massnahmen — die Umsetzung steht noch aus.

## Compatibility Impact
Workflow-Aenderung: Direkte Pushes auf main werden bei Aktivierung der
Required-Reviews durch PR-Flow ersetzt oder per dokumentierter Ausnahme
(Agent-Push mit Owner-Freigabe) geregelt.

## Security Impact
Positiv — Kernmassnahme gegen unautorisierte normative Aenderungen.

## Architecture Impact
Keiner.

## Migration Impact
Agent-Workflow (Aurora pusht direkt auf main) MUSS vor Aktivierung der
Required-Reviews geklaert werden: Option A = Agent stellt auf PR-Flow um,
Option B = dokumentierte Ausnahme mit Owner-Freigabe je Push.

## Decision
**ACCEPTED — Option B (Owner-Entscheidung).** Bereits angenommen mit der
ATC-STD-000 v1.0.0-Freigabe (07.09.2026, approval/APPROVAL-DECISION.md) und
bestätigt per Owner-Direktfreigabe "Alles freigeben" (07.09.2026, 20:00 UTC+2).
Physischer Stand (verifiziert 07.09.): Protected main aktiv (Required
Status Checks, Required Reviews, kein Force-Push, kein Löschen); Agent-
Direktpushes laufen als dokumentierte Owner-Ausnahme (enforce_admins: off,
1-Agent-per-Repo-Regel, Commit-Nachweis je Push). CODEOWNERS angelegt;
CI-Validierung (Validator + Repo-Audit) läuft je Push. Übergang auf vollen
PR-Flow gemäß AI-DEV-007 nach Ablauf der 30-Tage-Frist (07.10.2026).
