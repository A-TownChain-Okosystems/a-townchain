## Umgesetzt (atclang, crates/atc-core)
1. **Lexer Stage-2-Ausbau**: Token-Modell an Referenz-Lexer ausgerichtet — neue Tokens:
   Const, Return, Percent, Colon. (= Zuweisung im let-Kontext wie Referenz-EQ).
2. **AST (ast.rs)**: Expr (Int/Ident/Unary/Binary/Call), TypeHint, LetStmt, Program —
   mit kanonischer JSON-Serialisierung, bytgleich zum json.dumps(sort_keys=True, compact)
   der Python-Referenz (Differential-Kontrakt).
3. **Parser (parser.rs)**: Recursive Descent, Subset exakt nach frontend/parser/parser.py:
   Programmebene = let/const; Ausdrücke: + - * / (links-asssoziativ, * / vor + -),
   unäres Minus, Klammern, Funktionsaufrufe (Postfix, Schachtelung).
4. **Differential-Harness**: tools/differential/dump_reference.py generiert
   expected/*.json aus dem PYTHON-Referenz-Parser; Corpus 8 Dateien
   (let/const, Typ-Hints, Präzendenz, Parens, Unary, Calls, Mixed, No-Semi).
5. **CI-Anbindung**: differential-Job (Drift-Check: Referenz-Regeneration + git
   diff --exit-code; dann cargo test mit bytgleichem Vergleich) + rust-core-Job.

## Erster echter Differential-Befund (vor Landung)
`%` (PERCENT) wird vom Referenz-Lexer erzeugt, aber vom Referenz-Parser NICHT als
Operator akzeptiert (SyntaxError in parse_primary) — aus dem Corpus und dem
Rust-Operator-Subset entfernt. Genau dafür ist der Differential-Test da.

## Ehrlichkeits-Grenzen (bewusst)
- Subset: Programmebene nur let/const (Referenz erlaubt mehr via parse_statement-
  Fallback); fn-Definitionen, Kontrollfluss, Structs folgen in Stage 3
- Kein Typechecker/Bytecode-Backend (F-111)
- Python bleibt die Referenz; Rust ist der kanonische Kern IM AUFBAU — volle
  Parität wird über wachsendes Corpus erzwungen, nicht behauptet
