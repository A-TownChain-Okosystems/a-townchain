## Inhalt

### 1. Antrag

Festlegung des **AI Access Role Model** als Standard der AI-GOV-Familie: technische
Zugriffs-Rollenprofile fuer GitHub-Zugangs-Identitaeten von AI-Systemen auf
A-TownChain-Okosystems.

- **Stufe 1 — ATC-AUDITOR:** strikt read-only (Contents/Issues/PRs/Actions/Checks/Security-Alerts R); Zweck: Audits, Evidence-Collection; schreibt NIE.
- **Stufe 2 — ATC-DEVELOPER:** Code + Issues + PRs + Actions + Workflows + Checks (RW); KEIN Administration, KEIN Secrets; Merges nur nach Human Approval.
- **Stufe 2 — ATC-CI (eventgetrieben):** Status/Checks/Workflows + Webhook-Events → GSEPF Event Processor.
- **Stufe 3 — bewusst KEINE stehende AI-Identitaet:** Org-Administration bleibt Owner-reserviert; Ausnahmen nur zeitgebunden (< 24 h), zweckgebunden, evidence-geprueft, mit Owner-Freigabe.

### 2. Omni-Verbot (Kernentscheidung)

Eine Identitaet mit Administration + Secrets + Members + PAT-Verwaltung ist VERBOTEN
(Zirkularitaet: die Identitaet koennte eigene Kontroll-Gates umschreiben). Gegenentwurf zur
"ATC-Omni-Governance-Agent"-Maximalkonfiguration aus der Owner-Beratung 14.09. — diese wird
NICHT kanonisiert; stattdessen die gesplittete Profil-Architektur (§4/§9 des Standards).

### 3. Ehrlicher Ist-Zustand (Evidence-First)

- Aktives Token: klassisches PAT (repo, workflow, read:org, read:user) auf ShivaCoreDev (Org-Admin) — uebersteigt ATC-DEVELOPER; Migrationsbedarf auf Fine-grained dokumentiert (Runbook 14.09.).
- Branch-Protection: 27/30 Repos AUS (P0-Audit-Fund 14.09.) — Stufe-3-Owner-Aktion, priorisiert vor App-Architektur.
- F-ORG-002 (Dependency-Graph-Setting): weiterhin offen (Owner-Aktion).
