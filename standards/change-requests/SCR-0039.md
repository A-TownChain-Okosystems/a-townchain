## Befund (F-048, OBSERVE→ISOLATE→VERIFY abgeschlossen)

CI-Log Run #28 (atc-shivacore, HEAD 02824b88): `[FAIL] V-16 (CI/CD):
Conventional Commits nur 0% (<80%)` → `GATE: NO-GO`. Reproduktion per
Shallow-Clone Tiefe 1: exakt identisch. Ursache: `actions/checkout@v4`
klont defaultmäßig Tiefe 1 — V-16 wertet die letzten 20 Commits aus,
sieht aber genau EINEN Commit. Der nicht-konventionelle License-Batch-
Commit (SCR-0036/F-046, "license: …") als einziger sichtbarer Commit
ergab 0 % → 15 Repos org-weit rot (alle, deren letzter Commit der
License-Commit war). Grüne Repos hatten einen konventionellen HEAD
(1/1 = 100 %) — latenter Systemfehler blieb unbemerkt (seit AD-039-Sweep).

## Fix (zwei Ebenen)

1. **Workflow (22 Repos):** `fetch-depth: 0` am ersten Checkout von
   governance-ci.yml + `workflow_dispatch` als Trigger (manuelle
   Re-Audits möglich). Batch-Patch via GitHub-API, konventioneller
   Commit `fix(ci): …`.
2. **Defense in Depth (Audit-Tool):** atc-repo-audit V-16 erkennt
   flache Historie (≤ 2 Commits) und degradiert zu WARN statt MUST-FAIL
   — kein False-NO-GO mehr, auch wenn ein Workflow fetch-depth vergessen.
