## 3. Reconciliation findings

- `BLOB_MATCH` means only that the current file at the recorded path has the same Git blob SHA as the catalog entry. It does not prove that the function exists under the recorded name, has the described semantics, or is tested.
- `BLOB_DRIFT` means the file exists but its current blob differs from the catalog snapshot. Re-inspect the named symbol and refresh the catalog binding only after semantic review.
- `PATH_MISSING` includes proposed contract-only entries whose source path is `UNMAPPED`. They remain residual and must not be represented as implemented.
- Current comparison: ATCLang includes five changed source blobs and five unchanged blobs; ATC-VM's 29 mapped paths currently match their recorded blobs; ShivaCore has one changed blob and two unchanged; A-TownChain's three paths match; GlobusOS has two mapped paths matching and one unbound contract; Aurora AI has three changed mapped blobs and one unbound contract; Genesis Engine's two mapped blobs match.
- Catalog source commit SHAs can be older than current `main` while file blobs remain identical. Do not use commit mismatch alone as a stale-file verdict; compare the exact path/blob and verify symbol semantics.
