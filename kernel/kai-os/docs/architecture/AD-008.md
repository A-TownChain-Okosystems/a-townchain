# AD-008 — Language & Execution Architecture Decision

> **ATCLang defines deterministic, consensus-relevant execution.
> Rust implements the trusted carrier layer.
> The ATVM is the controlled execution boundary.**

## 1. Entscheidung (Rule 0 — Execution & Implementation Boundary)

Ersetzt die frühere Regel „Alles ist ATCLang":

> **ATCLang is the canonical language for deterministic on-chain execution.
> Rust is the canonical implementation language for the native node, OS-runtime,
> networking, security, storage, VM and hardware-facing infrastructure.
> The ATVM is the mandatory execution boundary between on-chain logic and
> native infrastructure.**

Und — noch wichtiger:

> **No consensus-critical semantic rule may exist solely as native Rust behavior
> without a corresponding canonical specification and deterministic verification path.**

Damit kann sich keine Consensus-Semantik heimlich in Rust einschleichen.

## 3. Consensus-Regel (präzisiert)

NICHT: „Rust darf keine Consensus-Logik enthalten." — zu absolut.

Stattdessen:

> Consensus-relevante Regeln müssen als kanonische, deterministisch spezifizierte
> VM-Ausführung definiert sein. Rust darf die VM, Netzwerk-, Storage- und
> Node-Infrastruktur implementieren, darf jedoch **keine alternative semantische
> Consensus-Implementierung außerhalb der kanonischen Ausführungsregeln** einführen.

Rust implementiert zwangsläufig Consensus-**Infrastruktur** (Block empfangen,
parsen, Signaturen prüfen, TX an ATVM übergeben, VM ausführen, State-Root
vergleichen, Block ablehnen, Peer bestrafen) — aber nicht die kanonische
Consensus-**Semantik**.

## 5. Fünf harte Prinzipien

**AD-008.1 — On-chain Canonicality**
Alles, was den kanonischen Chain-State deterministisch verändert, wird durch
ATCLang/ATVM definiert.

**AD-008.2 — Native Infrastructure**
Alles, was Betriebssystem-, Hardware-, Netzwerk-, Prozess-, Speicher- oder
Node-Funktionalität benötigt, wird nativ in Rust implementiert.

**AD-008.3 — VM Boundary**
ATVM ist die einzige reguläre Ausführungsgrenze zwischen On-chain-Code und
nativer Runtime.

**AD-008.4 — No Native Consensus Bypass**
Native Rust-Komponenten dürfen keine eigene alternative Consensus-Semantik
etablieren.

**AD-008.5 — Deterministic Verification**
Jede consensus-relevante ATCLang-Ausführung muss unabhängig reproduzierbar
und verifizierbar sein.

## 6. Zugriffskette (Security Boundary, nicht nur Compiler-Grenze)

ATCLang darf NIEMALS direkt auf Rust/OS-Ressourcen zugreifen:

```
ATCLang
   │  capability / syscall-like VM operation
   ▼
ATVM
   │  strictly validated interface
   ▼
Runtime Host API
   ▼
Rust
   ├── Storage
   ├── P2P
   ├── IPC
   ├── Sandbox
   └── Node
```

## 7. AI-Architekturregel

```
ATS / AI
   │  proposes
   ▼
ATCLang transaction / decision record
   ▼
ATVM
   │  canonical execution
   ▼
ATC State
```

> **AI may propose. ATCLang specifies. ATVM executes. ATC commits.**

Eine KI kann vorschlagen, optimieren, analysieren, vorbereiten — aber niemals
durch native AI-Ausführung den kanonischen Chain-State verändern.

## 8. GATE-008 — Language Boundary Compliance (automatisierbar)

CI/Agent-Audit prüft:

1. On-chain-Code → ATCLang
2. Native Runtime → Rust
3. Keine verbotenen OS-APIs aus ATCLang
4. Keine Consensus-Semantik ausschließlich in Rust
5. ATVM als Ausführungsgrenze
6. Deterministische Tests vorhanden
7. Unabhängige Verifikation vorhanden
8. Sprachmatrix entspricht Repository-Struktur

Damit ist AD-008 keine Dokumentation, sondern durchgesetzte Architekturpolitik.
